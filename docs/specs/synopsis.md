This repository explores **harness self-evolution**. Evolving directly from task trajectories can embed trajectory-specific patterns in the harness and overfit to benchmark scores, producing local patches rather than structural improvements. The core approach is to **separate training signals from testing**: training signals come from **user experience in simulated real-world usage**, while benchmarks remain **held out** and are used afterward to test whether experience-driven evolution improves capability. Benchmark results do not enter training or release gates.

The experiment simulates a **user usage → developer iteration** loop. **a | User side:** a user agent uses the harness over multiple turns according to a persona and seed scenario, producing experience scores (observation signals) and issues (bugs or requirements). **b | Developer side:** a single main trunk with no gates; a NexAU developer agent with Git tools claims an issue, checks out main, changes the harness, commits, creates a vK tag, and pushes directly. Later rounds can correct bad commits. **c | Feedback:** the next user session resolves the updated main HEAD, and the loop continues.

The evolving harness is a **launchable program with a black-box conversation contract**, rather than a single agent. Its entry point determines how one or more NexAU agents are orchestrated, and its source is hosted separately on Gitea. The developer commits and pushes directly to the main trunk, without a branch/merge/release workflow. The experiment tracks issue counts over time: a sustained failure to decline indicates harness degradation, while reaching zero too early suggests insufficient persona diversity and halted exploration.
